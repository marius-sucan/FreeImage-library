## F1 APNG writer stores GIF frames (any page without a BlendMethod tag) with blend_op SOURCE: transparent pixels punch holes
- Class: new-bug. Severity: Medium (High if QPV offers GIF->APNG conversion: transparency-optimised GIFs all break). Confidence: high.
- Where: PluginAPNG.cpp:81 (default blend_op = APNG_BLEND_OP_SOURCE), :1068-1071 (ReadFrameTags changes it only if "BlendMethod" exists), written :1335; 0f9863f. PluginGIF never sets BlendMethod; WebP (PluginWebP.cpp:699) and JXL (PluginJXL.cpp:2108) writers default to blend.
- Evidence: W/gen/d1/partial.gif (40x30; frame 1 20x10 at (5,5), left half transparent, disposal leave): `bin/ficonv_qpv -m 25 partial.gif 39 partial.apng.png`; `t/apng_oracle.py` -> `frame 1 ... dop 0 bop 0`; GIF_PLAYBACK vs APNG_PLAYBACK frame 1: 100 pixels differ (GIF [255 0 0 255], APNG [255 255 255 0]); independent decoder agrees with qpv's reader (file is wrong). fullopt.gif: 1184 of 1200 pixels transparent. Same pages saved as lossless WebP: 0 differing pixels.
- Fix sketch: pages with animation tags but no BlendMethod default to OVER (as WebP/JXL), or tag GIF frames with BlendMethod 0.
- **Fixed** in d6ac307, by the second sketch: GIF's raw frames, header-only ones too, say BlendMethod 0, as the frames of every other loader carry the tag; the WebP, JPEG XL and MNG writers read 0 as no tag, so only APNG output changes. The first sketch was left: pages with only a FrameTime, as QPV's Join images makes them, replace the canvas in APNG, and blending them would show each frame through the transparent parts of the next. partial.gif and fullopt.gif as APNG play as their GIF; 150 random GIFs copied page by page: 138 frames of 75 files differed from GIF_PLAYBACK on db31f2c, none now, and a compositor written from PNG 3 11.3.4 agrees on all 620 frames. test_gif_frames (TestAPI/APNG regress).

## F2 APNG writer stretches the contrast of 16-bit grey pages, each frame separately
- Class: new-bug. Severity: Medium. Confidence: high.
- Where: PluginAPNG.cpp:1124-1125 FreeImage_ConvertToStandardType(dib, TRUE); 0f9863f. The reader uses FreeImage_ConvertTo8Bits (high byte) at :754.
- What: scale_linear maps each frame's own min..max to 0..255 (ConversionType.cpp:102-140); flat frames clamp; animations flicker. Taken for any >= 2-page animation, or a single page with animation tags.
- Evidence: `bin/u16apng_qpv gen/d2/u16.png` (t/u16apng.c): page 0 gradient 1000..2008 (expected 3..7) saved as 0,85,170,255; page 1 flat 30000 (expected 117) saved as 255. Pillow reads the same.
- Fix sketch: FreeImage_ConvertTo8Bits(dib) (as RenderFrame), or write 16-bit APNG.
- **Fixed** in bf50b48, by the first sketch: FreeImage_ConvertTo8Bits(), the high byte, as APNG_PLAYBACK reads it, the page's profile kept for the conversion to the file's. The evidence comes back as 3-7 and 117. test_grey16_frames (TestAPI/APNG regress); the profile test's model of the writer takes the high byte too.

## F3 Animated PNGs identified as FIF_APNG (39); FreeImage_Validate(FIF_PNG) rejects them
- Class: compat-break (intentional, 0f9863f). Severity: Medium (agent). Confidence: high.
- Where: PluginPNG.cpp:335-357 (Validate FALSE when APNG_IsAnimatedStream, :348-354); PluginAPNG.cpp:264-295 (any acTL before IDAT); page list :494-515; ":399 num_frames is advisory".
- What: 54 of 419 Pillow test PNGs affected. GetFileType 39 vs 13; Validate(FIF_PNG) FALSE for a valid PNG; GetFIFFromFilename stays 13. Load(GetFileType(f)) on an APNG whose IDAT is not part of the animation returns the first fcTL frame, not the default image. Invalid num_frames files (conformance 047-050) play frames where the spec asks for the default image. Forcing FIF_PNG = main bit for bit on all 419.
- Evidence: `bin/validate_{qpv,main}` on dl/apngtests/002.png: 39 vs 13, Validate 0 vs 1; auto-load 002.png qpv green (anim frame) vs main red (default); 047.png qpv red, main green. W/out/apngauto/summary.txt.
- Fix sketch: document; optionally keep Validate(FIF_PNG) TRUE and choose inside GetFileType.
- **Fixed** in 3735925, by the optional sketch: Validate is upstream's again (the signature), and FreeImage_GetFileTypeFromHandle asks FIF_APNG once FIF_PNG validates, as it asks FIF_RAW after FIF_TIFF. GetFileType still names an animated PNG FIF_APNG, FreeImage_Validate(FIF_PNG) is TRUE for it, and with FIF_APNG disabled it is FIF_PNG (db31f2c: FIF_UNKNOWN); 711 files are named as before. Documented in README.md, under the APNG line. Kept: FIF_APNG's page 0 is the first frame, not a static image the animation leaves out (PNG 3 4.9.1: that image "is not considered to be a frame"); FIF_PNG reads it, as main does. num_frames: 2427471 shows the static image for a count of 0 ("0 is not a valid value"; Firefox's png_set_acTL and Chrome's PNG codec ignore such an acTL). Other counts that disagree with the fcTL chunks (047-050) still play the frames the file holds: the spec asks to treat them as errors, which neither browser does (by their sources, both play the frames there are, up to the count), and ffmpeg writes 0xFFFFFFFF when its output cannot seek back to write the real count; the stricter reading is left open. test_detection (TestAPI/APNG regress); "an acTL counting no frames" (robust).

## F4 GIF and APNG count a frame cut before its first row: header-only describes it, full load returns NULL
- Class: new-bug. Severity: Low. Confidence: high.
- Where: PluginGIF.cpp:720 (Open keeps a frame once its first sub-block length byte is read) vs :1290-1294 (Load throws "frame holds too little data"); header-only branch :1217 never checks; a03b1f1, ca839e8, 42c553b. APNG: PluginAPNG.cpp:446-448, :485-492 keep a frame with any fdAT bytes; PNG loader refuses no decoded row (PluginPNG.cpp:722-725); cda7638.
- Evidence: gen/d5/cut3.gif `bin/nopix_qpv 25 0`: page 1 full NULL, header-only 60x40 4bpp; gen/d5a/cut6.png page 9 full NULL, header-only 60x45, APNG_PLAYBACK NULL. main GIF Open fails (0 pages); no APNG.
- Fix sketch: drop such frames when building the page list, or return the blank frame.
- **Fixed** in b95953c, by the first sketch: such a frame is no page. GIF's Open replays Load()'s decoding of the frame the file ends in, without a bitmap, until a row comes out, and applies Load()'s bound on the data for the frame's 8-bit raster, the largest any flag gives it; the APNG parser has libpng read that frame's first row as FIF_PNG sets it up, without its messages, and keeps the frame as FIF_PNG's salvage does (a one-row frame cut in its zlib trailer stays). A file whose only image is cut so does not open, as a GIF frame whose data never starts. cut3.gif has 1 page, cut6.png 9. Cut at 200 lengths each, 46 GIFs (9785 cuts) and 174 APNGs (Pillow's, the conformance suite and 59 written from random GIFs; 46895 cuts) count only pages that load, header-only and played alike; on db31f2c 301 cuts of 41 GIFs and 4326 of 172 APNGs counted a page that did not load. test_cut_pages (TestAPI/APNG robust), testGIFCutFrames (TestAPI testMPage). Found on the way: a file cut inside an fcTL or an fdAT's sequence number lost its animation, its whole frames included (fixed in dcf8503; longer cuts of the APNG sweep lost frames 321 times on db31f2c, twice now, where a cut reaches the error of an invalid file); a GIF cut inside a comment after its frames read the comment for ever, until the memory ran out (fixed in 0af9f47; Pillow's comment_after_last_frame.gif took a test process to 11 GB).

## F5 APNG writer: when frame 0 does not cover the canvas, the default image (IDAT) is fully transparent
- Class: new-bug (interop). Severity: Low. Confidence: high.
- Where: PluginAPNG.cpp:1308-1320 (first_is_default false -> CompressBackdrop :1257-1268 writes a blank IDAT not in the animation); 0f9863f.
- Evidence: gen/d13/small0.gif (60x40 screen, frame 0 30x20 at (10,5)) -> `ficonv_qpv -m 25 small0.gif 39 small0.apng.png`: chunks IHDR sRGB gAMA cHRM pHYs acTL IDAT(32) fcTL fdAT fcTL fdAT IEND; `fidump_main -f 13`: 60x40 max alpha 0; Pillow n_frames 3 default_image True.
- Fix sketch: write frame 0 padded on a transparent canvas as IDAT with a full-canvas fcTL.
- **Fixed** in 157554a, as sketched, for animations of two frames or more: frame 0, read back from its data, is padded with transparent black and written as IDAT with an fcTL covering the canvas (PNG 3 4.9.1: the default image "should be appropriately padded with fully transparent black pixels"). Playback is unchanged: the first frame draws on a transparent canvas, where both blend operations agree, and its disposal clears or restores pixels that were transparent anyway. small0.gif as APNG: IDAT is frame 0 at (10,5), Pillow reads 2 frames and no default image. A frame saved alone keeps the transparent static image: the multi-page cache saves each page alone and reloads it as the page it was, under its own FrameLeft and FrameTop, so a padded page would come back as large as the canvas at its offset. 150 random GIFs as APNG, 149 with a first frame smaller than the screen, play as their GIF, the PNG 3 compositor agrees, and Pillow sees no separate default image (149 on db31f2c). test_padded_first_frame (TestAPI/APNG regress).
